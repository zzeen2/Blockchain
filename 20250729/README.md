# 브릿지 오라클

## 브릿지의 구조
> 이더리움 체인에서 Lock 컨트랙트 실행 자산을 잠금처리 -> Lock 이벤트 발생
> 브릿지에서 relayer에서 이벤트 감지 다른 네트워크의 컨트랙트에서 wETH mint 요청을 호출
> 다른 네트워크의 wETH는 이더와 동일한 가치를 가지는 토큰 -> 유동성 풀을 가지고 있는 DEX 거래소에서 스왑이 가능하다.

### Lock 컨트랙트 생성
1. 스왑을 요청하는 지갑의 일정 자산을 잠금
2. 잠금처리된 자산을 이후에 소각 또는 언락 할 수 있는 구조
3. 이벤트 발생되면 relayer에서 감지를 할 수 있는 이벤트명을 사용
> Lock 컨트랙트는 자산을 잠가놓는 금고내용처럼 보면 된다
> Lock 컨트랙트는 자산을 송금하면 잠금처리하고 잠금 처리에 대한 이벤트를 호출해서 입금의 증명을 한 뒤 브릿지의 relayer에서 이벤트를 구독하고있다가 이벤트가 발생하면 스왑을 요청하는 네트워크에 wETH의 토큰을 민팅

### lock 컨트랙트 내부 구조
1. 사용자들의 잠금 금액을 표현
2. 총 잠금 금액
3. Lock 이벤트 호출

## 주의
> 금전적인 스왑의 내용을 작성할때 주의할점
> 재진입 공격방지 인터렉션 패턴과 뮤텍스 패턴을 잘사용해서 작성

### Wrapped Tokken 
> 메인넷의 자산을 다른 네트워크에서 표현하기 위해서 사용하는 토큰
> w를 붙여서 wETH 이런식으로 자산을 표현한다. wBETH 등
> 단순히 erc20 규격으로 만들어진 토큰 표준 => 상호작용 가능한 DEX에서 스왑을 할 수 있다.

#### 스왑 구조 현상태(단방향 브릿지)
이더리움(Sepolia)에서 이더를 Lock하고, 이를 감지하여 카이아(Kaia) 네트워크에서 WrappedToken(wETH)을 mint

| 네트워크    | 스마트컨트랙트            | 역할                            |
| ------- | ------------------ | ----------------------------- |
| Sepolia | `Lock.sol`         | 사용자가 ETH를 입금(Lock)하면 이벤트 발생   |
| Kaia    | `WrappedToken.sol` | 이벤트를 듣고 `mint()`를 호출해 **wETH** 발행 |

[ 사용자 ]
   │
   ▼
Sepolia에서 lock() (ETH 보내기)
   │
   ▼
Lock 컨트랙트에서 Locked 이벤트 발생
   │
   ▼
bridge.js가 이벤트 감지
   │
   ▼
Kaia 네트워크의 WrappedToken에 mint(account, value) 호출
   │
   ▼
사용자 계정에 wETH 발행됨!
